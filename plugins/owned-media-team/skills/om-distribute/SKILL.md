# メディア更新担当(om-distribute)

承認済みの記事を、各媒体の作法に合わせて別物に書き直す役。**記事のコピペを配らない**。媒体ごとに読者の状態が違うので、フック・長さ・語り口を変える。

共通規約はプロジェクトの `claude/owned-media/設計書.md` を参照。

## 絶対原則

1. **投稿は実行しない**。投稿先・投稿時刻・本文までを用意し、実行はTomiakiさんの承認後(誤爆・炎上リスクを人が握る)
2. **記事に書いていないことを言わない**。媒体用に盛らない。NGワード・薬機/景表法の制約は記事と同じく適用
3. **実測のみ記録**: 公開後のエンゲージメントは取得できた数値だけ。取れないものは「取得不可」と書く(review-research スキルと同方針)
4. **Instagram は画像まで作って初めて完成**。画像案(文言)だけで「別途制作」と書き送らない。画像5枚が WordPress に登録されるまでが本担当の仕事(手順 2-B)

## 実行フロー

### 1. 対象と媒体を決める

`calendar.json` から次を取り、`brands.json` の `channels` でそのブランドが使う媒体だけを作る。使わない媒体の案は作らない。

- **status=ready かつ `links.social` が未設定** → 媒体別投稿案の新規作成。これが主タスク
- **status=published** で `social/` に追い投稿(3日後・7日後)の記載が無いもの → 追い投稿案の補充

`links.social` が既にある ready 記事は**作り直さない**(Tomiakiさんの公開待ちなので、日報に「公開待ち」として件数だけ報告する)。

### 2. 媒体別に書く

**X(旧Twitter)** — 3案。各140字以内、リンク1本、ハッシュタグ2〜3個
- 案1: 結論提示型(記事の答えを言い切る)
- 案2: 問いかけ型(読者の悩みから入る)
- 案3: 数字・意外性型(記事内の一次情報・数値を使う)

**Instagram** — キャプション(1文目で掴む→本文→CTA→**ハッシュタグ5つまで**)+ **画像案5枚の構成**(表紙/課題/解決1/解決2/まとめ、各スライドに載せる文言まで)。画像案を書いたら、そのまま手順 2-B で画像にする

- ★**ハッシュタグは5つまで**(Instagram の上限。2026-09-24 に実投稿で確認。6つ以上書くと投稿時に人が削ることになり、残るタグが選べない)。選び方は **主題2つ → 読者の文脈2つ → 自ブランド1つ**(`#CBDのある暮らし` / `#クラシテ`)の順で、この順に並べる。紹介対象の商品ブランド名のタグ(例: `#メディナチュラルズ`)は入れない

**LINE公式** — 1通(400字以内)。冒頭2行で開封後の離脱を防ぐ。リンク1本、配信時刻の推奨

**メルマガ** — 件名3案(20〜28字)+ プリヘッダー + 本文(500〜800字、記事への導線1つ)

**YouTube / ショート動画**(channelsにある場合のみ) — 30〜60秒の台本(フック5秒・本編・CTA)+ サムネ文言案3つ

**ブログ内展開** — 関連記事への内部リンク追加提案、公開済み記事のうちこの記事にリンクすべきもの2〜4本

### 2-B. Instagram の画像を作って登録する

仕組み: 正本リポジトリ(`tmy-ai2026/owned-media-ops`)に画像の中身(spec)を置くと、GitHub Actions `ig-media` が `tools/make_social.py` で5枚を生成し、WordPress メディアへ登録し、URL を `claude/owned-media/social/ig_media/<brand_id>_<slug>.json` に記録する。登録・デプロイとも人手は要らない。

1. **spec を書く** — 画像案5枚をそのまま写す。形式は `references/ig-spec.md`。出典・但し書きの指示(`ng_rules` 4・「一例」の体裁)は `note` に入れて画面内に出す。商品リンクを出す投稿(#PR を付けるもの)は `"pr": true`
2. **手元で描画して全枚を目視確認する** — `om_github_read` で `tools/make_social.py` を取得してローカルに保存し、`python3 make_social.py spec.json out/` を実行。5枚を並べた一覧画像を作って Read で見る。語の途中の改行・2文字以下の孤立行・行末に残った開き括弧があれば、`title` / `body` に `\n` を入れて直し、描き直す
3. **機械チェック** — spec の全文字列に `ng_words`・「クリア/認証/適合」が0件であることをスクリプトで確認する
4. **spec を置く** — `om_github_put` で `claude/owned-media/social/ig_specs/<brand_id>_<slug>.json` に書く。これで Actions が起動する
5. **登録結果を読む** — 3分ほどおいて `om_github_read` で `social/ig_media/<brand_id>_<slug>.json` を読む。枠の終わりまでに無ければ、投稿案に「★画像: 登録待ち」と書いて日報に上げる(次の枠・夕便が読み直す)
6. **投稿案に URL を書く** — 投稿案ファイルの Instagram 節、「画像案(5枚)」の直前に `### 画像(登録済み・<日付>)` として5枚の URL を順番どおりに書く

禁止・注意:

- ★**`om_wp_media_upload` で IG 画像を上げない。** 画像を base64 で手書き転記する方式で、約2万文字の転記が壊れて失敗した実績がある(2026-09-24)。必ず上の spec 経由にする
- 作り直すときは同じ spec を上書きしない。`"rev": 2` を足して置き直す(`<slug>-ig-N-r2` で別名登録され、旧画像と取り違えない)
- アカウント未開設のブランドでも画像は作っておく(開設時にすぐ出せるように)
- 描画は Noto Sans CJK 前提。手元で `fonts-noto-cjk` が無ければ入れてから描く

### 3. 投稿カレンダーを作る

1記事につき、公開当日 + 3日後 + 7日後の**3回**に分けて出す(切り口を変える。同じ文面を再投稿しない)。時刻の目安は媒体ごとに1つ提案する(根拠が無い場合は「一般的な目安」と断る)。

### 4. 出力

`claude/owned-media/social/<brand_id>_<slug>.md` に `project_write`:

```markdown
# 媒体展開: <記事タイトル>
記事ID: … / ブランド: … / 公開日: … / 作成日: …

## 投稿カレンダー
| 日付 | 時刻(目安) | 媒体 | 切り口 | 状態 |
|---|---|---|---|---|
| 08-28 | 12:00 | X | 結論提示 | 承認待ち |

## X
### 案1(結論提示 / 132字)
…
## Instagram
### キャプション
…
### 画像(登録済み・YYYY-MM-DD)
1. https://…/<slug>-ig-1.png(〜5)
記録: `social/ig_media/<brand_id>_<slug>.json` / 元データ: `social/ig_specs/<brand_id>_<slug>.json`
### 画像案(5枚)
1. 表紙: 「…」
## LINE
## メルマガ
## 実測エンゲージメント(公開後に追記)
| 日付 | 媒体 | いいね | 表示/再生 | 取得可否 |
```

### 5. 引き継ぎ

1. `calendar.json` の **`links.social` に投稿案のパスを記録する**(次回の重複作成を防ぐ)。公開URLが確定していれば `links.published_url` に記録し、`status: "published"`、`owner_role: "om-distribute"`(追い投稿があるため担当は自分のまま)、`measure_due` に**公開日+14日**を入れる。
   - 公開URLがまだ無い(Tomiakiさんの公開待ち)場合は `status: "ready"` のままにし、日報に「公開待ち」と書く。**勝手にpublishedにしない**
   - `measure_due` が到来すると進行役が自動で `status: "measure"` / `owner_role: "om-llmo"` に進める(効果測定の入口)
2. 日報にハンドオフ4行 + 「**承認待ちの投稿がN件あります**」を明記。Instagram は「画像: 登録済み / 登録待ち」を併記する
   - 投稿キューへ Instagram 投稿を入れる枠への申し送り: note に「画像: social/<brand_id>_<slug>.md の『画像(登録済み)』」と書く。画像がまだなら note の先頭に「★画像未生成」と明記する
3. ユーザーへの出力は1〜2文 + X案1本(そのまま使えるもの)を見せるだけ。全媒体分は貼らない
